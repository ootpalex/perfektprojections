## ⏵ STATSPLUS API TOKENS (2026-09-30, newest)

- **Why:** the StatsPlus creator wrote that the API will soon require "the token" on almost every endpoint, not only /ratings. Until now the project sent the browser cookie pair on /ratings only. Every other request went out with no login and no check of the reply, so a refusal would have parsed as junk or empty data with exit 0 (the audit found 10 such call sites, e.g. /teams writing numeric orgs, /contract zeroing salaries, /draft wiping the saved pick list).
- **The token:** one per team per league, so TGS and BLM each have their own; 36 characters. Where: log in on statsplus.net, open the league, click Prefs (top right, next to Logout), API Token box, copy the Current Token. It expires 90 days after StatsPlus made it.
- **`Set StatsPlus Tokens.bat` (NEW, repo root) = `ingest/statsplus_token.py --set`:** asks for the TGS token, then the BLM token. The paste does not show on screen; Enter on an empty line keeps the saved token or skips the league. StatsPlus checks each token first (/tokencheck/, then the team in that league's /teams list). A token is refused when StatsPlus calls it invalid or expired, when StatsPlus can't be reached, or when it is the token saved for the other league. When the check gives no clear answer (no /tokencheck/ page, no team ID in the reply, a team not in the list), the token is saved with a WARNING and the first pull says plainly if StatsPlus refuses it. File: `%LOCALAPPDATA%\TGS Projections\statsplus_tokens.json`, outside the repo. The token is never printed; the ratings log lines and StatsPlus errors pass through `statsplus.redact`. Other flags: `--check` (asks StatsPlus about each saved token), `--clear TGS|BLM`, `--have TGS,BLM` (exit 0 when saved; the bats use it). `--have`, `--check` and the pull report warn once a token is more than 80 days old (counted from the day it was saved): run the bat again then.
- **Every request sends it, and a refusal stops the step loudly:** all StatsPlus traffic goes through `statsplus._get`, which adds `?token=<league token>` on its own (https statsplus.net only; every redirect must stay on the site, else nothing is sent). Every reply is checked now. A refusal (token expired or unknown, login needed, too soon, not enabled, HTTP 401/403/429, a login page, or a reply without its required columns) raises `StatsPlusRefused`. The caller prints the reason with the fix (e.g. "the TGS token has expired. Get a new one from StatsPlus Prefs and run Set StatsPlus Tokens.bat.") and exits nonzero with nothing written. With no token saved, `_get` sends the same request as before.
- **Cookies only as the fallback:** `Get StatsPlus Ratings.bat` and `Get StatsPlus History.bat` ask for `sessionid` + `csrftoken` only for a league with no saved token. With both tokens saved, Get StatsPlus Ratings updates TGS and BLM in one run and asks for nothing, so the per-league browser login limit no longer applies. With one token, it asks for the other league's cookies (Enter skips that league). `Update Draft Board.bat`, `Update Dispersal Board.bat` and `Bank Season.bat` never asked for a login; their steps now send the token, and the bats say "NOT updated" / "NOT done" when a step fails.
- **Exit codes (new or changed):** `refresh.py` 2 = no token and no cookie, 3 = no token and the cookie is for the other league, 7 = StatsPlus refused a request (the message says why), 8 = StatsPlus not reachable for the ratings (network, timed out, or an address on another site). `draft.py` 3 = refused (nothing written, the saved pick list kept), 4 = dispersal could not reach StatsPlus. `fetch_actuals.py` 3 = refused or an empty feed, 4 = not reachable (nothing moved or written in either case). `snapshot_projections.py` 3 / 4, the same for /date (nothing snapped). `metadata_inputs.py` 3 = refused (no input CSV or manifest written). `statsplus_history.py` 2 and 3 now cover the token; 10 = the check job for today's ratings failed for another reason (no ratings, not reachable, too slow, too soon again and again).
- **Fewer repeat downloads:** `fetch_*(cache=True)` reuses a reply saved in `ingest/.cache/sp/<slug>/` while the league's in-game date (/date) has not moved and the reply is under 6 hours old. The repeat paths use it: `refresh.py --from-cache` (Recalibrate and every Grind cycle), ratings_db /teams, growth_lenses, metadata_inputs, the history tool's /players. Live pulls, the draft board and the dispersal board read fresh (`fresh=True`).
- **History tool (`statsplus_history.py`):** (1) Overlap skip: when the newest live pull is from today's game date and a token is saved, no overlap ratings job runs. One /tokencheck call proves the token and that live pull is today's view, which saves a 5-minute job (`--force-overlap` runs it anyway). When the league has played on since the newest live pull, a ratings job with no date gives today's view; it is never stored. (2) No-snapshot memory: `ingest/.cache/asof/<slug>/_no_snapshot.json` remembers each date StatsPlus had no snapshot for (empty reply, today's ratings, ages that fit another day, a repeat) and why. Later runs skip those dates with no job; `--retry-missing` asks again. Network, too-soon and error-page failures are not remembered. (3) Today's-ratings refusal: a past date answered with today's ratings is refused and remembered, and the run goes on. Exit 7 now needs 3 step dates in a row like that AND no past date accepted this run. Also new: a later-roster guard (rebuilt ages that put more than 2% of players under 14 mean a later roster: refused), a one-job probe that settles a repeated snapshot pair (report line MOVED or CHECK), and a mid-run login stop that still prints the report of the dates stored before it.
- **Tested only against a local mock:** fake tokens, a 127.0.0.1 mock server, a network guard. Nothing has been sent to statsplus.net yet. Unverified: the /tokencheck/ reply format (a plain id, JSON or "team id N" are all read; a 404 or an unreadable reply means `--set` saves the token with a WARNING), the words StatsPlus will use to refuse the formerly public endpoints, and whether the ratings poll URL needs the token (it always gets it). First real use: run Set StatsPlus Tokens.bat, then Get StatsPlus Ratings.bat, and read the messages.
- **Open:** history KNOWN LIMIT A4 (StatsPlus answers a missing date with an odd EARLIER snapshot and today's ages: stored under the date asked for; the report flags rebuilt ages, no DB flag). The User-Agent is still "Mozilla/5.0"; StatsPlus asks for one that names the tool. README.md still says Get StatsPlus Ratings pulls "the signed-in league". WHICH BUTTON.docx now has Set StatsPlus Tokens.bat; Get StatsPlus History.bat is still left out until its first successful run.

## Win-model lenses on the Roster Optimizer (this session)
A **model selector** (segmented buttons, top-right of the page) re-scores the SAME roster through five win models so the user can see *more ways* to read "most wins." - **Runs foundation.** Real RS/RA reconstructed from columns already in the JSON: offense = lineup `BatR`+`BSR` (PA-weighted by the vR share), run environment = each MLB team's **actual** staff (top-5 SP by `WAA wtd` + top-8 RP by `WAA wtd RP`, innings-weighted 62/38, averaged league-wide → ~**4.47 R/G**; this avoids the 40-man scrub tail that inflates a naive mean to 5.13). `RPW = 1.5·lgRG + 3` (Tango). **RS−RA is pinned to the linear run differential** `(weightedLineupWAA + pitcherWAA)·RPW`, so Pythagorean and Linear agree at average and differ only by the curve — never by a bookkeeping gap.
- **Linear** — the existing `81 + WAA` (unchanged default).
- **Pythagorean** — PythagenPat `x=(R/G)^0.287`, `Win%=RS^x/(RS^x+RA^x)`. Cubs: linear 92 → pyth **93** (+1, as expected; the two only diverge in the tails, e.g. ALL-orgs 127→122).
- **Monte Carlo** — `monteCarloSeason()`, 2,500 seeded (mulberry32 + Box-Muller, reproducible) seasons: each perturbs RS/RA by projection uncertainty, draws a Pythagorean true-talent win%, plays 162 Bernoulli games. Returns median/floor(p5)/ceiling(p95) + `pGE85..pGE100` odds + a win histogram. Cubs: median 93, floor 81, ceiling 105, P(90+) 68%. **NOTE: the "90-win playoff line" is a proxy, not a real league sim** (labeled as such in the UI). - **Durability** — `durabilityWeighted:true` flag haircuts each player's value columns by a playing-time factor (`PRONE_FACTOR`: Iron Man .99 … Wrecked .68, × current-DL penalty) via `applyDurability`, then **re-runs the same selection** (a durable solid bat can beat a fragile star) and re-scores.
